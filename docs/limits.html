Ограничения

Bot Machine — не универсальный фреймворк для всех ботов. Вот где он заканчивается.

Код, не визуальный редактор

Flow описывается в TypeScript. Нет drag-and-drop, конструктора или админки. Это осознанно: код можно тестировать, ревьюить и генерировать AI-агентом.

TypeScript и Zod

Без типов и схем фреймворк теряет половину смысла. Если проект на чистом JavaScript, лучше взять что-то проще.

Telegram-контекст

BotContext знает про Update, chat, message, callback_query. Для WhatsApp, VK или веба нужен отдельный адаптер. Мультиканальность — в планах, не в 0.1.11.

Сессии

  • In-memory по умолчанию: данные теряются при перезапуске.
  • Redis-хранилище есть, но его нужно подключить и обслуживать.
  • Нет TTL из коробки.
  • Нет блокировок: два одновременных update могут перезаписать сессию.

Один polling-процесс

На один токен — один startPolling. Для нескольких инстансов нужен webhook или внешняя блокировка.

Нет CRM и аналитики

Фреймворк не хранит лиды, не считает воронку и не отправляет карточки менеджеру. Это задачи приложения.

Нет LLM-runtime

Bot Machine помогает AI-агенту писать код, но не вызывает модель. Если нужен LLM в диалоге, добавьте его в команду или отдельный сервис.

Нет версионирования flow

Если вы переименовали состояние, старые сессии с flowState могут сломаться. Миграций нет; продумайте совместимость или очистку сессий при деплое.

Сравнение

Задача Bot Machine grammY / Telegraf
Многошаговый сценарий flow из коробки вручную или плагин
Роутинг Express-подобный middleware/роутер
Схемы данных Zod на входе и выходе вручную
Визуальный редактор нет нет
Полный Bot API через telegram-client да
Низкий порог входа нужен TS ниже

Когда не использовать

  • Один экран и две кнопки: обычный обработчик проще.
  • Нужен полный контроль над Bot API: берите grammY/Telegraf.
  • Нужен визуальный конструктор: это не он.
  • Нужен мультиканальный бот сегодня: адаптеров нет.
