FAQ

Это low-code?

В смысле «меньше кода на сценарий» — да. В смысле «без кода» — нет.

Bot Machine убирает повторяющиеся части: роутинг, сессии, переходы, клавиатуры, ответы. Сценарий всё равно описывается в TypeScript. Такой low-code удобен для AI-агентов: у flow, view и command явные границы.

Внутри есть LLM?

Нет. Фреймворк не вызывает модели и не принимает решения. Он помогает AI-агенту писать и менять код, но runtime детерминирован.

Нужна ли persona?

Нет. В Bot Machine её нет. Участник диалога — Telegram user id и сессия. Persona — отдельная экспериментальная абстракция для омниканальности, не часть FSM-движка.

Почему не grammY или Telegraf?

Они дают доступ к Bot API и middleware. Bot Machine даёт модель сценария: flow, состояния, view, command. Если нужен полный контроль над API, берите grammY/Telegraf. Если нужен читаемый многошаговый сценарий — Bot Machine.

Можно ли на JavaScript?

Технически да, но теряются типы и часть смысла. Фреймворк рассчитан на TypeScript и Zod.

Как добавить новый экран?

Добавьте ключ в createFlow:

const flow = createFlow("appointment", {
  index: {...},
  service: {...},
  confirm: {...}
});

Затем добавьте переход:

nextState: "confirm"

Как сохранить данные между сообщениями?

Через ctx.session. Подключите session() и пишите в сессию из команды.

Как пережить перезапуск?

Подключите RedisSessionStore. In-memory сессии теряются.

Как тестировать без Telegram?

Создайте фейковый AppContext и вызывайте FlowController.handle или router.route. Пример — в Тестах.

Где смотреть примеры?

  • examples/appointment.ts — полный сценарий записи.
  • examples/demo.ts — консольный прогон.
  • examples/appointment.test.ts — тест сценария.
  • src/flows/ — счётчик и переименование.

Какая версия актуальна?

Документация описывает стабильную 0.1.11. Ветка 0.2.0 меняет API и находится в разработке.

Можно ли использовать в коммерческом проекте?

Да, лицензия MIT. Проверьте зависимости и замените демо-токены.
