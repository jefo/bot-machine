# Текстовый ввод

Текст в flow обрабатывается через `onText`. Паттерн может захватывать значение в `ctx.params`.

## Захват значения

```ts
name: {
  component: async () => ({
    text: "Как вас зовут?\n\nНапишите имя одним сообщением."
  }),
  onText: {
    ":name": {
      command: createCommand({
        name: "saveName",
        input: z.object({ name: z.string().min(1) }),
        execute: async ({ name }, ctx) => {
          ctx.session.name = name;
        }
      }),
      nextState: "phone"
    }
  }
}
```

Пользователь пишет `Иван`:

- паттерн `:name` захватывает `"Иван"`;
- `ctx.params.name = "Иван"`;
- команда получает `{ name: "Иван", text: "Иван" }`;
- flow переходит в `phone`.

## Несколько параметров

```ts
onText: {
  "заказ :id :status": {
    command: updateStatusCommand,
    refresh: true
  }
}
```

Текст `заказ 42 paid` → `ctx.params = { id: "42", status: "paid" }`.

## Точное совпадение

```ts
onText: {
  "помощь": {
    command: helpCommand,
    nextState: "help"
  }
}
```

Совпадает только сообщение `помощь` целиком. Для подстроки используйте RegExp.

## RegExp

```ts
onText: {
  /^\+?\d{10,15}$/: {
    command: savePhoneCommand,
    nextState: "confirm"
  }
}
```

RegExp проверяется через `text.match()` — без якорей он найдёт подстроку.

## Валидация

Zod-схема — единственное место, где описаны правила:

```ts
input: z.object({
  phone: z.string().regex(/^\+?\d{10,15}$/, "Некорректный номер")
})
```

Если текст не прошёл, команда не выполнится, flow покажет ошибку. Для дружелюбного сообщения обработайте ошибку сами или используйте отдельное состояние.

## Текст и кнопки в одном состоянии

```ts
onText: {...},
onAction: {...}
```

Сначала flow проверяет callback, потом текст. Можно принимать и кнопки, и свободный ввод.

## Когда не нужен текст

Если значение можно выбрать кнопкой, выбирайте кнопку: меньше ошибок и не нужна валидация формата.

Текст уместен для:

- имени;
- телефона;
- email;
- свободного описания задачи.
